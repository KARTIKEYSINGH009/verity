Rules alone: 0% recall

Heuristics only catch attacks phrased like known patterns. On novel wording they are a safety net, not a shield — which is why the learned layer exists.

Classifier alone: 84% recall

The trained model generalizes to new phrasings. Per-category recall on this run — social engineering, impersonation, data theft, multilingual, spacing: 100%. Weakest classes: harmful content (50%) and fraud (67%).

Known limitations

The training set is a prototype baseline (200 examples) and grows through the corrections loop. False-positive rate is 10% on deliberately hard benign prompts. The faithfulness heuristic (the judge’s offline fallback) scores 75% verdict accuracy on an 8-case mini-eval in benchmarks.json (unsupported-answer precision 1.0, recall 0.5); the LLM judge is primary in live mode. No filter can guarantee complete protection — Verity reduces risk and records evidence; it does not eliminate either.

Keep your client. Change the route.

Verity exposes an OpenAI-compatible chat completions endpoint, so the integration is a base-URL swap—not an application rewrite.

  • FastAPI proxy gateway
  • Mock mode works without an API key
  • Business-policy enforcement via policy_context
  • Faithfulness grading via grounding_context
  • Blocked requests return a structured 400: blocked_by_verity_guard / blocked_by_verity_policy
  • Traces are admin-only: /v1/traces needs VERITY_ADMIN_KEY and is disabled when no key is set
  • Public-endpoint abuse controls: 20k-char input cap, per-client rate limit
  • Graceful fallback when judge or classifier is unavailable

curl -X POST https://verity-nine-flame.vercel.app/v1/chat/completions \

Trust, stated plainly.

Verity inspects AI traffic, so its own behavior has to be inspectable too.

Open source (MIT)

Full source, training data, and benchmark scripts are public under the MIT license: github.com/KARTIKEYSINGH009/verity. Found a bypass? That is a contribution — new attacks enter the reviewed corrections loop and make the next model stronger.

Data handling

Your deployment stores its own traces (inputs, outputs, flags, latency) in its own database — you set retention. In live mode, answer text is sent to your chosen judge model under your provider key. This public demo runs in mock mode; its traces live in ephemeral storage and reset on redeploy — and the traces endpoint is disabled here, because traces contain raw prompts. Found a vulnerability? Please report it through GitHub Security Advisories on the repository instead of opening a public issue.

Screening is not authorization

Verity classifies content and enforces declared policy on requests and answers. It is not an authorization system: sensitive actions (refunds, transfers, record changes) must also be permission-checked at your tool and backend boundary. Never let a model answer alone authorize one.
