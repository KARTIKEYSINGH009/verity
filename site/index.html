Benchmarks

Measured, not promised.

Held-out benchmark: 45 prompts the model never trained on — 25 fresh attacks in new phrasings (including multilingual and spacing-obfuscated), 20 deliberately hard benign near-misses. Threshold checked on a separate 16-prompt validation set. Reproduce it from the repository with python scripts/run_benchmarks.py; full data in benchmarks.json. These are internal measurements on a small set — a signal, not an independent security certification. Last measured 2026-10-27.

Why recall, precision and F1 differ: three different ratios — recall is 23/25 attacks detected, precision is 23/24 flagged that were attacks, F1 is their harmonic mean. Raw counts are in the cards above and in benchmarks.json.

Rules alone: 8% recall

Heuristic patterns caught 2 of the 25 held-out attacks — they only fire on attacks phrased like known patterns. On novel wording they are a safety net, not a shield — which is why the learned layer exists.

Classifier alone: 88% recall

The trained model generalizes to new phrasings. Per-category recall on the combined gateway run — injection, impersonation, multilingual, spacing, harmful content, social engineering: 100%; data theft and fraud: 67%.

Known limitations

The training set is a prototype baseline (568 examples, including Hindi, Hinglish, Spanish, German, French, Arabic, Russian, Chinese, Japanese, Korean and several Indian languages, plus emotional-manipulation cases) and grows through the corrections loop. On a 50-prompt multilingual pilot set it scored full recall with no false alarms; per-language claims wait for a larger independent evaluation. False-positive rate is 5% at the gateway on deliberately hard benign English prompts. No filter can guarantee complete protection — Verity reduces risk and records evidence; it does not eliminate either.

Integration

Keep your client. Change the route.

Verity exposes an OpenAI-compatible chat completions endpoint, so the integration is a base-URL swap — not an application rewrite.

  • FastAPI proxy gateway
  • Mock mode works without an API key
  • Business-policy enforcement via policy_context
  • Faithfulness grading via grounding_context
  • Blocked requests return a structured 400: blocked_by_verity_guard / blocked_by_verity_policy
  • Traces are admin-only: /v1/traces needs VERITY_ADMIN_KEY and is disabled when no key is set
  • Public-endpoint abuse controls: 20k-char input cap, per-client rate limit
  • Graceful fallback when judge or classifier is unavailable
# Start Verity locally
pip install -r requirements.txt
export VERITY_MOCK_MODE=true
uvicorn verity.gateway:app --port 8000

# Point the client at Verity
client = OpenAI(
    base_url="http://localhost:8000/v1",
    api_key="your-provider-key"
)
localhost quickstart

ROADMAP

Trust

Trust, stated plainly.

Verity inspects AI traffic, so its own behavior has to be inspectable too.

Open source (MIT)

Full source, training data, and benchmark scripts are public under the MIT license on GitHub. Found a bypass? That is a contribution — new attacks enter the reviewed corrections loop and make the next model stronger.

Screening is not authorization

Verity classifies content and enforces declared policy on requests and answers. Sensitive actions (refunds, transfers, record changes) must also be permission-checked at your tool and backend boundary.

Responsible disclosure

Found a vulnerability? Please report it through GitHub Security Advisories on the repository instead of opening a public issue.

Use cases

Where Verity fits.

Customer support chatbots

The beachhead: storefront and D2C bots that take refund, discount and account questions — exactly the prompts attackers jailbreak into unauthorized offers.

Internal copilots and agents

Tools that read tickets, docs and inboxes ingest untrusted text all day. Screening every role catches instructions smuggled into that content before the agent acts on them.

Regulated and high-trust flows

Intake, onboarding and servicing flows where a hallucinated promise is a compliance incident. Grounding checks flag answers that outrun the provided context.

Frequently asked questions.

What is included in the free plan?

A personal account on this site: your own API key, a dashboard with your requests and traces, and gateway screening (guard, policy checks, grounding evaluation) against a mock model. Free keys are limited to 1,000 requests per month, enforced by the gateway.

Can I use my own model provider?

Yes — on a pilot deployment. Verity is OpenAI-compatible and provider-agnostic: during provisioning your deployment is pointed at your provider (OpenAI, Groq, Anthropic-compatible endpoints, self-hosted) with your key, which never passes through any Verity form or chat.

Do you store my data?

It depends on the context. Free account: traces are stored in the site's database (hosted in Singapore), visible only to you, pruned after 30 days, never used for training. Public playground: logged and pruned the same way, attached to no account. Your own deployment: traces live in your database, under your control, and never pass through this site.

What are the current limitations?

Streaming responses are not passed through yet. The free tier runs a mock model. Self-serve live deployments are in development — today, live traffic means a founder-led pilot. Verity is not an authorization system: permission-check sensitive actions in your own backend.

Can I get a dedicated deployment?

Yes — that is exactly what a pilot is: your own deployment, keys and database, isolated by architecture, with weekly founder reports and success criteria agreed in writing.
